# MID-064 · Estimation and delivery — Quiz

Outcomes: O1 clarify requirements · O2 vertical slicing · O3 ranges and risk-first · O4 communicate progress.

**Q01 (O1)** Good acceptance criteria are: A. Testable examples B. Vague goals C. Implementation notes D. Estimates
**Q02 (O1)** Before building a vague request you should: A. Start coding B. Choose the database C. Ask questions and confirm in writing D. Estimate in days
**Q03 (O2)** A vertical slice: A. Builds all tables first B. Is one layer C. Is a refactoring only D. Cuts through all layers to deliver a small piece of value
**Q04 (O2)** Which is a horizontal slice? A. Customer requests a return B. Approve a return C. All database work first D. Send a refund notification
**Q05 (O2)** A good slice size is roughly: A. A quarter B. One hour C. Two weeks D. One to three days
**Q06 (O3)** A better estimate is: A. Exactly 5 days B. As soon as possible C. 3-6 days, 80% confident, with stated assumptions D. 10 days plus padding
**Q07 (O3)** A spike is: A. A time-boxed investigation that answers a question B. A permanent feature C. A bug D. A release
**Q08 (O3)** Risky slices should be done: A. Last B. Never C. By juniors only D. First, to learn early
**Q09 (O4)** When you see slippage you should: A. Report it early with options B. Wait for the deadline C. Add padding silently D. Cut tests
**Q10 (O4)** Best progress report: A. "90% done" B. Silence C. Hours worked D. Slices done, remaining, and updated range with risks

Q01 A · Q02 C · Q03 D · Q04 C · Q05 D · Q06 C · Q07 A · Q08 D · Q09 A · Q10 D
