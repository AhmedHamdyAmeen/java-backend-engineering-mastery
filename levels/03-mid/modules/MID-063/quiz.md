# MID-063 · Technical documentation — Quiz

Outcomes: O1 ADRs · O2 RFCs and design docs · O3 C4 and sequence diagrams as code · O4 runbooks.

**Q01 (O1)** An ADR records: A. All code changes B. Meeting minutes C. A deployment log D. One significant decision with context, options, and consequences
**Q02 (O1)** When should an ADR be written? A. A year later B. When the decision is made C. Only after incidents D. Never for rejected options
**Q03 (O1)** An outdated ADR should be: A. Deleted B. Edited silently C. Marked superseded by a new ADR D. Hidden
**Q04 (O2)** An RFC is most useful for: A. Typo fixes B. Daily tasks C. Bug tickets D. Changes costly to reverse or affecting other teams
**Q05 (O2)** A non-goal in a design doc states: A. A goal that failed B. A risk C. What the proposal deliberately does not solve D. A deadline
**Q06 (O3)** C4 level 2 shows: A. Classes B. Users and external systems only C. Containers such as services, databases, and brokers D. Methods
**Q07 (O3)** Why keep diagrams as code? A. They are prettier B. They need no tools C. They replace ADRs D. They can be reviewed, diffed, and versioned with the system
**Q08 (O3)** A sequence diagram is best for showing: A. Messages between participants over time B. Deployment topology C. Database schema D. Team structure
**Q09 (O4)** A good runbook includes: A. Only the root cause theory B. The team org chart C. Source code D. Symptoms, checks, mitigation, escalation, and recovery verification
**Q10 (O4)** Alerts should: A. Be silent B. Link to a runbook C. Replace dashboards D. Avoid naming impact

## Answers
Q01 D · Q02 B · Q03 C · Q04 D · Q05 C · Q06 C · Q07 D · Q08 A · Q09 D · Q10 B

## Practical part
Five exercises `MID-063-EX01` to `EX05` plus the lab. Pass: documentation review with no missing legends or alternatives, and a peer answering the ten questions from the docs alone.
