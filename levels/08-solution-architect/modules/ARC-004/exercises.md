# ARC-004 · Architecture frameworks — Exercises and lab

## Lab
### ARC-004-LAB1 · Tailored method
**Outcomes:** 1–4 · **Time:** ~2.5 h
1. List the framework phases and artifacts you could use for the Larkspur engagement.
2. Select a tailored subset and give each artifact a named consumer and the decision it supports.
3. Map each stakeholder group to the views that address their concerns.
4. Define governance checkpoints with decision-makers and compliance criteria.
5. Write a tailoring rationale based on program size and risk.
**Acceptance:** no artifact without a named consumer.

## Exercises (case-based; six exercises)
| ID | Outcome | Task |
| --- | --- | --- |
| ARC-004-EX01 | 1 | Explain the ADM to a Larkspur sponsor in five plain sentences without framework vocabulary. |
| ARC-004-EX02 | 1 | Place six Larkspur activities (vision statement, capability map, options paper, migration plan, build governance, change requests) on the ADM phases. |
| ARC-004-EX03 | 2 | For five stakeholders, write their main concern and the view that addresses it. |
| ARC-004-EX04 | 2 | A diagram claims to serve "all audiences". Identify the viewpoint problem and split it into two views. |
| ARC-004-EX05 | 3 | Design three governance checkpoints for the program: when, who decides, inputs, possible outcomes. |
| ARC-004-EX06 | 4 | Compare the method for a one-team internal tool and the Larkspur program; list what you drop and what you keep, and why. |

## Solutions
- **EX01** Example: we first agree the goal, then describe the business, data, applications, and technology today and tomorrow, choose options, plan the move, and guide the build; we repeat as we learn.
- **EX02** Vision statement → Architecture Vision; capability map → Business Architecture; options paper → Opportunities and Solutions; migration plan → Migration Planning; build governance → Implementation Governance; change requests → Architecture Change Management.
- **EX03** CFO: cost and ownership, capability and cost view; security: data flows and trust boundaries; store managers: process and device view; engineers: component view; operations: deployment and monitoring view.
- **EX04** One overloaded diagram mixes concerns; split into a business view for sponsors and a component and interface view for engineers, each with legend and question.
- **EX05** Options review (sponsor and EA decide direction), design review (design authority, approve or conditions), pre-go-live review (operations and security, go or no-go).
- **EX06** Small tool: context diagram plus decision log; Larkspur: add capability map, options paper, integration view, governance. Rationale: size, risk, regulatory exposure, number of teams.

**Workplace evidence:** an architecture method you tailored for a real program.
