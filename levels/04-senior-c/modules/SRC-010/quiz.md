# SRC-010 · Architecture documentation — Quiz

Outcomes: O1 audience-tailored architecture description · O2 docs as code · O3 runbooks · O4 design docs.

**Q01 (O1)** One document written for every audience: A. Serves all well B. Is cheapest and best C. Is required D. Serves none well
**Q02 (O1)** A subsystem description mainly needs C4 levels: A. Code only B. Context and containers, plus selected components C. Class diagrams for every class D. None
**Q03 (O1)** Why keep diagrams as text? A. They diff and review like code B. They are prettier C. They are smaller D. Tools require it
**Q04 (O2)** Docs as code means: A. Docs live in the repo and change in the same PR as code B. Docs are written in Java C. Docs are never reviewed D. Docs are generated only
**Q05 (O2)** A useful CI check for docs: A. Compile speed B. Test coverage only C. Link and diagram build checks D. Line count
**Q06 (O3)** A runbook step should be: A. "Investigate" B. A specific action with an expected result C. A long essay D. Optional
**Q07 (O3)** The best test of a runbook: A. A peer executes it without help B. The author reads it C. A manager approves it D. A spell check
**Q08 (O3)** A runbook must include: A. Author biography B. Company history C. Rollback and escalation D. Source code
**Q09 (O4)** A design doc should start with: A. Background history B. The decision needed and who decides C. Appendices D. Credits
**Q10 (O4)** To get a decision in one review you should: A. Present one option B. Hide risks C. Skip a recommendation D. Present options with trade-offs and a recommendation

## Answers
Q01 D · Q02 B · Q03 A · Q04 A · Q05 C · Q06 B · Q07 A · Q08 C · Q09 B · Q10 D

## Practical part
Six documentation exercises `SRC-010-EX01` to `EX06` plus the lab pack. Pass: quiz at least 8/10, at least five exercises correct, and a documentation review passing (COM dimension weighted higher) with a runbook a peer executes without help.
