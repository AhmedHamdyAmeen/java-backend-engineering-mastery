# JNR-053 · Team workflows — Quiz

Outcomes: O1 branching · O2 pull requests · O3 code review · O4 issues and agile.

**Q01 (O1)** In trunk-based development, changes are merged to `main`: A. Monthly B. Never C. At least daily in small steps D. Only by the lead
**Q02 (O1)** A downside of long-lived branches: A. Easy merges B. Large, risky merges C. Faster CI D. Cleaner history
**Q03 (O2)** A good pull request is: A. Small with one purpose B. Large and mixed C. Without description D. Without tests
**Q04 (O2)** A PR description should explain: A. Only the file names B. Nothing C. Why, how it was tested, and risks D. The author's weekend
**Q05 (O3)** A reviewer should look first at: A. Spacing B. Correctness and tests C. Variable colors D. Commit time
**Q06 (O3)** A constructive comment is: A. "This is wrong." B. "Who wrote this?" C. "Obviously bad." D. "This fails for an empty list; could we add a test?"
**Q07 (O3)** As an author, when you get a comment you: A. Ignore it B. Argue always C. Respond and explain or change D. Delete it
**Q08 (O4)** An issue should include: A. Acceptance criteria B. Only a title C. Passwords D. A rewrite of the app
**Q09 (O4)** A retrospective is for: A. Showing finished work B. Reviewing how the team works and improving it C. Assigning blame D. Estimating budgets
**Q10 (O4)** A board column order that fits a workflow: A. Done, To do, Review B. Review, Done, To do C. To do, In progress, In review, Done D. Random

## Answers
Q01 C · Q02 B · Q03 A · Q04 C · Q05 B · Q06 D · Q07 C · Q08 A · Q09 B · Q10 C

## Practical part
Seven exercises `JNR-053-EX01` to `EX07` plus the lab; assessed on PR and review quality. Pass: quiz 8/10, at least five exercises correct, every lab change merged through a reviewed PR, and retro notes written.
